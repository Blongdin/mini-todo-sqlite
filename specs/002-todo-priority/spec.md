# Feature Specification: Todo 중요도(Priority)

**Feature Branch**: `002-todo-priority`

**Created**: 2026-09-19

**Status**: Draft

**Input**: User description: "Todo에 중요도(priority) 기능을 추가한다.

요구사항:
- 각 Todo는 priority를 가진다.
- priority는 High, Medium, Low 세 단계다.
- 새 Todo를 추가할 때 priority를 선택할 수 있다.
- priority를 선택하지 않으면 기본값은 Medium이다.
- Todo 목록에서 각 항목의 priority를 확인할 수 있어야 한다.
- 기존의 추가, 조회, 완료 토글, 삭제 기능은 그대로 유지한다.
- priority도 SQLite에 저장되어 새로고침이나 재실행 후에도 유지되어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Todo 생성 시 중요도 지정 (Priority: P1)

사용자는 새 Todo를 추가할 때 High, Medium, Low 중 하나를 중요도로 선택할 수 있다.

**Why this priority**: 중요도 지정은 이 기능의 핵심 가치로, 이것 없이는 기능이 존재하지 않는 것과 같다. 다른 모든 사용자 스토리(기본값, 목록 확인)는 이 스토리 위에서 의미를 가진다.

**Independent Test**: 새 Todo 추가 화면에서 중요도를 "High"로 선택하고 저장한 뒤, 해당 Todo가 High 중요도로 생성되었는지 확인함으로써 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 새 Todo 추가 화면에 있음, **When** 제목을 입력하고 중요도로 "High"를 선택한 뒤 추가함, **Then** 새 Todo가 High 중요도로 생성된다.
2. **Given** 사용자가 새 Todo 추가 화면에 있음, **When** 제목을 입력하고 중요도로 "Low"를 선택한 뒤 추가함, **Then** 새 Todo가 Low 중요도로 생성된다.

---

### User Story 2 - 중요도 미선택 시 기본값 적용 (Priority: P2)

사용자가 Todo를 추가하면서 중요도를 별도로 선택하지 않으면, 시스템은 자동으로 Medium을 중요도로 지정한다.

**Why this priority**: 사용자가 매번 중요도를 강제로 선택해야 한다면 기존 사용 흐름(빠른 Todo 추가)을 해치므로, 합리적인 기본값을 통해 기존 경험을 보존해야 한다.

**Independent Test**: 중요도를 선택하지 않고 Todo를 추가한 뒤, 해당 Todo의 중요도가 Medium으로 저장되어 있는지 확인함으로써 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 새 Todo 추가 화면에 있음, **When** 중요도를 선택하지 않고 제목만 입력하여 추가함, **Then** 새 Todo는 Medium 중요도로 생성된다.

---

### User Story 3 - 목록에서 중요도 확인 (Priority: P1)

사용자는 Todo 목록을 볼 때 각 항목에 지정된 중요도(High/Medium/Low)를 바로 확인할 수 있다.

**Why this priority**: 중요도를 지정할 수 있어도 목록에서 확인할 수 없다면 기능의 실질적 가치가 없다. 중요도 확인은 생성 기능과 동등하게 핵심적이다.

**Independent Test**: 서로 다른 중요도를 가진 여러 Todo를 생성한 뒤 목록 화면을 열어, 각 항목 옆에 해당 중요도가 표시되는지 확인함으로써 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** High, Medium, Low 중요도를 가진 Todo가 각각 하나 이상 존재함, **When** 사용자가 Todo 목록을 조회함, **Then** 각 Todo 항목 옆에 해당 중요도가 명확히 표시된다.

---

### User Story 4 - 기존 기능 및 데이터 지속성 유지 (Priority: P1)

사용자는 중요도 기능이 추가된 이후에도 기존의 Todo 추가, 조회, 완료 토글, 삭제 기능을 동일하게 사용할 수 있으며, 중요도를 포함한 모든 데이터는 새로고침이나 앱 재실행 후에도 유지된다.

**Why this priority**: 기존 기능의 퇴행(regression)은 사용자 신뢰를 해치며, 중요도 데이터가 저장되지 않으면 이 기능 전체가 무의미해진다.

**Independent Test**: Todo를 추가/완료 토글/삭제하고, 중요도가 지정된 Todo를 만든 뒤 페이지를 새로고침(또는 앱을 재실행)하여 모든 Todo와 그 중요도, 완료 상태가 그대로 유지되는지 확인함으로써 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 여러 중요도의 Todo가 존재함, **When** 페이지를 새로고침함, **Then** 모든 Todo가 원래의 제목, 완료 상태, 중요도와 함께 그대로 표시된다.
2. **Given** 중요도가 지정된 Todo가 존재함, **When** 사용자가 해당 Todo의 완료 상태를 토글함, **Then** 완료 상태만 변경되고 중요도는 그대로 유지된다.
3. **Given** 중요도가 지정된 Todo가 존재함, **When** 사용자가 해당 Todo를 삭제함, **Then** 해당 Todo와 중요도 정보가 목록에서 사라지고 다른 Todo는 영향받지 않는다.

---

### Edge Cases

- 사용자가 유효하지 않은 중요도 값(예: "Urgent" 또는 빈 값)을 지정하려 하면 시스템은 이를 거부하거나 기본값(Medium)으로 대체해야 한다.
- 중요도 기능 도입 이전에 이미 존재하던 Todo(만약 있다면)는 Medium을 기본 중요도로 부여받아 목록에 정상적으로 표시되어야 한다.
- 동일한 중요도를 가진 Todo가 여러 개 존재해도 각 항목은 독립적으로 표시되고 개별적으로 삭제/토글 가능해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 모든 Todo에 대해 High, Medium, Low 중 하나의 중요도 값을 가지도록 해야 한다.
- **FR-002**: 시스템은 사용자가 새 Todo를 추가할 때 중요도를 세 단계(High/Medium/Low) 중에서 선택할 수 있는 수단을 제공해야 한다.
- **FR-003**: 사용자가 Todo 추가 시 중요도를 선택하지 않으면, 시스템은 해당 Todo의 중요도를 Medium으로 자동 지정해야 한다.
- **FR-004**: 시스템은 Todo 목록의 각 항목에 해당 Todo의 현재 중요도를 표시해야 한다.
- **FR-005**: 시스템은 기존의 Todo 추가, 조회, 완료 상태 토글, 삭제 기능을 중요도 도입 이후에도 변경 없이 그대로 제공해야 한다.
- **FR-006**: 시스템은 Todo의 완료 상태 토글 또는 삭제 작업 시 다른 Todo의 중요도에 영향을 주지 않아야 한다.
- **FR-007**: 시스템은 각 Todo의 중요도를 영속적으로 저장하여, 페이지 새로고침이나 애플리케이션 재실행 후에도 각 Todo가 마지막으로 지정된 중요도를 유지하도록 해야 한다.
- **FR-008**: 시스템은 유효하지 않은 중요도 값이 저장되지 않도록 해야 한다(허용값: High, Medium, Low).

### Key Entities

- **Todo**: 할 일 항목을 나타내며, 제목, 완료 여부, 그리고 중요도(High/Medium/Low, 기본값 Medium) 속성을 가진다. 각 Todo는 독립적으로 생성, 조회, 완료 토글, 삭제, 중요도 확인이 가능하다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 새 Todo를 추가하면서 별도의 추가 학습 없이 10초 이내에 중요도를 선택하고 저장을 완료할 수 있다.
- **SC-002**: 중요도를 지정하지 않고 생성된 Todo의 100%가 Medium 중요도로 저장된다.
- **SC-003**: Todo 목록을 조회하는 사용자는 별도의 클릭이나 추가 동작 없이 각 항목의 중요도를 한눈에 식별할 수 있다.
- **SC-004**: 페이지 새로고침 또는 애플리케이션 재실행 이후에도 이전에 저장된 모든 Todo의 중요도 값이 100% 정확히 보존된다.
- **SC-005**: 중요도 기능 도입 이후에도 기존 사용자가 수행하던 Todo 추가/조회/완료 토글/삭제 작업의 성공률은 기존과 동일하게 유지된다(회귀 없음).

## Assumptions

- 이 저장소의 기존 Todo 애플리케이션은 이미 영속적인 데이터 저장소를 사용하고 있으며, 중요도 값도 동일한 저장소의 Todo 레코드에 함께 저장되는 것을 전제로 한다.
- 중요도의 세 단계는 정렬(High > Medium > Low)이 가능한 순서를 가지나, 이번 기능 범위에서는 목록을 중요도순으로 자동 정렬하거나 필터링하는 요구사항은 포함하지 않는다(명시적으로 요청되지 않음).
- 중요도는 Todo 생성 시점에만 선택 가능한 것으로 간주하며, 생성 이후 기존 Todo의 중요도를 수정하는 기능은 이번 범위에 포함하지 않는다(명시적으로 요청되지 않음).
- 단일 사용자(또는 인증 개념이 없는) 로컬 Todo 애플리케이션이라는 기존 전제를 유지하며, 권한/역할에 따른 중요도 제어는 범위에 포함하지 않는다.
